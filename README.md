# subtitle-align

ทำซับไตเติลภาษาไทยที่**เวลาไม่เหลื่อม** แม้ย่อคำให้สั้นกว่าที่พูดจริง

## ปัญหาที่แก้

ให้ Gemini ถอดเสียงออกมาเป็น `.srt` แล้วเอาเข้า CapCut มักเจอว่าซับกับเสียงเหลื่อมกัน
และยิ่งเหลื่อมหนักเมื่อย่อคำให้สั้นลงเพื่อเน้นคำสำคัญ

สาเหตุไม่ใช่ Gemini ถอดผิด — มันถอดแม่น แต่ timestamp ที่ให้มาเป็นการ**ประมาณจากบริบท**
ไม่ได้จับคู่กับเสียงจริง และมันมาเป็นก้อนละประโยค พอลบคำออกครึ่งประโยค
เวลาของก้อนไม่รู้เรื่องด้วย ซับเลยขึ้นตั้งแต่ต้นประโยคทั้งที่คำที่เหลืออยู่กลางประโยค

ตัวอย่างจากคลิปทดสอบจริง — ย่อ "วันนี้เราจะมาคุยกันเรื่องการนอนหลับให้มีคุณภาพ"
เหลือ "การนอนหลับให้มีคุณภาพ":

| | เวลาที่ซับขึ้น | ผล |
|---|---|---|
| ใช้เวลาของก้อนเดิม | 1.24 | ขึ้นเร็วไป 2 วินาที |
| **subtitle-align** | **3.24** | ตรงกับที่คำว่า "การนอน" ดังจริง (3.30) |

## หลักการ

แยก **ข้อความ** ออกจาก **เวลา** แล้วให้แต่ละอย่างมาจากเครื่องมือที่ถนัดที่สุด

```
ไฟล์เสียง
   ├─→ Gemini ────────→ ข้อความ (แม่นเรื่องคำไทย ศัพท์เฉพาะ ชื่อคน)
   └─→ Whisper align ─→ เวลาของทุกตัวอักษร (จับคู่กับเสียงจริง)
                            ↓
                       words.json
                            ↓
                   คุณย่อคำใน edit.txt
                            ↓
          ค้นคำที่เหลือกลับใน words.json แล้วหยิบเวลาของคำนั้นมาใช้
                            ↓
                        .srt ที่ตรงคำ
```

เพราะทุกตัวอักษรมีเวลาของตัวเองติดอยู่ ย่อคำยังไงเวลาก็ตามได้เสมอ

# ใช้งาน

## แบบเร็ว 3 ขั้น

```bash
# 1. ถอดข้อความ + จับคู่กับเสียง
python3 align.py ~/Desktop/clip.mp4

# 2. เปิด work/clip/edit.txt แล้วย่อคำตามต้องการ

# 3. สร้าง SRT
python3 make_srt.py clip
```

ได้ `work/clip/clip.srt` ลากเข้า CapCut ได้เลย

**ครั้งแรกจะโหลด Whisper model ~1.4GB** ครั้งเดียว หลังจากนั้นไม่ต้องโหลดอีก
alignment กินเวลาราวครึ่งหนึ่งของความยาวคลิป (คลิป 3 นาที ≈ 1.5 นาทีบน Mac M-series)

## ไฟล์ที่ได้ใน work/&lt;ชื่องาน&gt;/

| ไฟล์ | คืออะไร | แก้ได้ไหม |
|---|---|---|
| `audio.flac` | เสียง 16kHz mono ที่ดึงออกจากวิดีโอ | ลบได้ ถ้าอยากเริ่มใหม่ |
| `transcript.txt` | ข้อความดิบจาก Gemini | **แก้ได้** ถ้าถอดผิดคำ แล้วรัน `align.py` ซ้ำ |
| `words.json` | เวลาของทุก token ที่จับคู่กับเสียงจริง | **ห้ามแก้** |
| `edit.txt` | ไฟล์กลางสำหรับย่อคำ | **แก้ตรงนี้** |
| `<ชื่องาน>.srt` | ผลลัพธ์ | ผลจาก `make_srt.py` |

## กติกาของ edit.txt

ไฟล์หน้าตาแบบนี้ — บรรทัดที่ขึ้นต้นด้วย `#` เป็นคำอธิบาย ไม่ต้องแตะ

```
[2] 00:00:01.240 → 00:00:05.560
วันนี้เราจะมาคุยกันเรื่องการนอนหลับให้มีคุณภาพ

[3] 00:00:05.560 → 00:00:08.840
หลายคนคิดว่านอนแปดชั่วโมงแล้วจะพอ
```

บรรทัดเวลาเป็นแค่ข้อมูลอ้างอิง **ไม่ต้องแก้** — ระบบคำนวณเวลาใหม่จากคำที่เหลือเอง

**ลบคำที่ไม่อยากให้ขึ้น**

```
[2] 00:00:01.240 → 00:00:05.560
การนอนหลับให้มีคุณภาพ
```

ซับจะเริ่มตรงที่คำว่า "การนอน" ดังจริง ไม่ใช่ต้นประโยค

**ตัดทั้งก้อนทิ้ง** — ลบข้อความจนเหลือบรรทัดว่าง

```
[7] 00:00:20.180 → 00:00:23.640

```

**แยกเป็นสองซับ** — ใส่ `|` คั่น แต่ละฝั่งได้เวลาของตัวเอง

```
[5] 00:00:12.720 → 00:00:17.300
สิ่งที่สำคัญกว่า | คือความสม่ำเสมอ
```

**ห้ามพิมพ์คำใหม่ที่ไม่มีในเสียง** เพราะจับเวลาไม่ได้ — ถ้าเกิดขึ้น `make_srt.py`
จะเตือนว่าก้อนไหน แล้วถอยไปใช้เวลาของก้อนเดิมแทน

## ตัดคลิปสั้นจากคลิปยาว

**กฎเหล็ก: align กับเสียงชุดสุดท้ายที่คนดูจะได้ยินเสมอ**
ถ้าตัดต่อเพิ่มหลังทำซับ เวลาจะเลื่อนทั้งหมดและกลับไปเป็นปัญหาเดิม

**กรณีตัดหัวท้ายอย่างเดียว** — ไม่ต้อง export ก่อน สั่งจากไฟล์เต็มได้เลย

```bash
python3 align.py full.mp4 --from 12:30 --to 13:05 --max-chars 24
```

เวลาใน SRT จะนับ 0 ที่ 12:30 ตรงกับคลิปที่ตัดออกมาพอดี
รูปแบบเวลาที่รับ: `90` (วินาที), `1:30`, `12:30.5`, `1:02:30`

**กรณีมี jump cut ข้างใน** — ตัดใน CapCut ให้จบ export ออกมาก่อน แล้วค่อย

```bash
python3 align.py ~/Desktop/cut30.mp4 --max-chars 24
```

**หาช่วงที่จะตัดจากคลิปยาว** — pipeline นี้ไม่ได้ทำมาสำหรับไฟล์ยาว (ไม่มีการแบ่ง chunk)
คลิปเกิน ~10 นาทีให้ถอดหาช่วงด้วยเครื่องมืออื่นก่อน แล้วค่อย align เฉพาะช่วงที่จะใช้

# ตัวเลือกทั้งหมด

## align.py

| flag | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `--from` | — | ตัดเฉพาะช่วง เริ่มที่ (เวลาใน SRT นับ 0 ที่จุดนี้) |
| `--to` | — | ตัดเฉพาะช่วง จบที่ |
| `--max-chars` | `42` | ตัวอักษรสูงสุดต่อซับหนึ่งก้อน (คลิปแนวตั้งใช้ `24`) |
| `--max-gap` | `0.4` | ช่วงเงียบกี่วินาทีถึงตัดก้อนใหม่ |
| `--model` | `medium` | `small` / `medium` / `large-v3` |
| `--device` | `cpu` | `cpu` / `mps` / `cuda` |
| `--name` | ชื่อไฟล์ | ชื่อโฟลเดอร์งาน |
| `--work` | `./work` | โฟลเดอร์เก็บงาน |

## make_srt.py

| flag | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `--min-dur` | `0.7` | ความยาวขั้นต่ำต่อซับ กันซับกระพริบ |
| `--lead` | `0.06` | เผื่อเวลาก่อนคำแรก ให้ซับขึ้นก่อนเสียงนิดหนึ่ง |
| `--tail` | `0.18` | เผื่อเวลาหลังคำสุดท้าย |
| `--gap` | `0.04` | ช่องว่างขั้นต่ำระหว่างซับสองก้อน |
| `--window-pad` | `0.6` | ขยายกรอบค้นหาของแต่ละก้อน |
| `-o` | `work/<ชื่อ>/<ชื่อ>.srt` | path ไฟล์ผลลัพธ์ |
| `--work` | `./work` | โฟลเดอร์เก็บงาน |

# แก้ปัญหา

**`CERTIFICATE_VERIFY_FAILED` ตอนโหลด Whisper model**
`align.py` ตั้ง `SSL_CERT_FILE` จาก certifi ให้แล้ว ถ้ายังเจอ เช็คว่า `pip3 install certifi` แล้ว

**ถอดผิดคำ หรือตกคำ**
แก้ `work/<ชื่อ>/transcript.txt` แล้วรัน `align.py` ซ้ำ — มันจะข้ามขั้นเรียก Gemini
เพราะไฟล์มีอยู่แล้ว แล้ว align ใหม่จากข้อความที่แก้

**ซับก้อนยาวเกินไป**
ลด `--max-chars` แต่ระบบตัดได้เฉพาะตรงรอยเว้นวรรค ถ้าคลิปพูดรัวไม่มีจังหวะหยุด
ก้อนจะยาวกว่าที่ตั้งไว้ — เป็นข้อจำกัดของภาษาไทยที่ไม่มีช่องว่างระหว่างคำ

**ซับขึ้นเร็วหรือช้าไปทั้งไฟล์**
ปรับ `--lead` / `--tail` ตอน `make_srt.py` ไม่ต้อง align ใหม่

**"จับคู่กับเสียงไม่ได้ชัด" ตอน make_srt**
ก้อนนั้นมีคำที่ไม่มีในเสียง แก้ให้ใช้คำเดิมแล้วรันซ้ำ

**อยากเริ่มใหม่ทั้งหมด**
ลบโฟลเดอร์ `work/<ชื่อ>/` แล้วรัน `align.py` ใหม่

# ข้อจำกัด

- ทดสอบกับเสียงพูดไทยที่ค่อนข้างชัด ยังไม่ได้ทดสอบกับเสียงเพลงคลอดัง
  หรือคนพูดทับกันสองคน
- `--from` / `--to` ใช้ได้เฉพาะกรณีตัดหัวท้าย ถ้ามี jump cut ข้างในต้อง export
  คลิปที่ตัดเสร็จแล้วมา align ใหม่
- ไม่มีการแบ่ง chunk — คลิปยาวเกิน ~10 นาทีจะช้าและอาจติด limit ของ Gemini
- Whisper ตัด token ภาษาไทยเป็นตัวอักษรเดี่ยว การแบ่งก้อนจึงอาศัยการเว้นวรรค
  ที่ Gemini ใส่ตามจังหวะพูด ไม่ใช่การตัดคำแบบ dictionary

# ข้างในทำงานยังไง

`align.py`
1. `ffmpeg` ดึงเสียงเป็น FLAC 16kHz mono (ตัดช่วงตาม `--from`/`--to` ถ้ามี)
2. ส่งให้ Gemini ถอดเป็นข้อความล้วน — prompt สั่งไม่ให้ใส่ timestamp
   ให้เว้นวรรคตรงจังหวะที่คนหยุดพูดจริง และเขียนตัวเลขเป็นตัวหนังสือตามที่ได้ยิน
3. `stable-ts` เอาข้อความไป forced-align กับเสียง ได้เวลาของทุก token
4. จับ token เป็น "วลี" ตามรอยเว้นวรรค แล้วแพ็ควลีเป็นก้อนซับตาม `--max-chars`

`make_srt.py`
1. กางเวลาของ token ออกเป็นระดับตัวอักษร (เกลี่ยเชิงเส้นภายในหนึ่ง token)
2. เทียบข้อความที่ย่อแล้วกับตัวอักษรในกรอบเวลาของก้อนนั้นด้วย `SequenceMatcher`
3. เอาเวลาของตัวอักษรแรกและตัวสุดท้ายที่จับคู่ได้มาเป็น start/end
4. เผื่อหัวท้าย บังคับความยาวขั้นต่ำ กันซับซ้อนทับกัน และไม่ให้ล้นออกนอกคลิป
